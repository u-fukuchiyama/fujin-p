# あわみ：文書スケルトン作成の依頼

このファイルの後半に，あわみキャンバスの全ダンプ（awami-canvas-export 形式の JSON）が付いています．
依頼者が別途示す「作りたい文書」の記述に従って，このキャンバスのノードを素材とする文書の骨組み（スケルトン）を作ってください．
スケルトンはあわみの「📑 スケルトンに基づく文書生成」ページの「📂 スケルトンで展開」に読み込まれ，FUJIN-P が各ノードの実体 URL の文書を取得して本文として流し込み，一つの HTML 文書に仕上げます．
したがって，スケルトンに書くのは構成（節立てとノードの配置）と，節をつなぐ短い地の文だけです．ノードの文書の中身を要約して書き写す必要はありません．

## ダンプの読み方

nodes[] の各要素がノード（ナラティブ素）です．id，label，url（実体 URL），note（注記）を持ちます．
edges[] の各要素が結合子です．label.name が結合子の名前（具体化・展開・詳細など），inputs[] から outputs[] へ向かう関係を表します．
結合子の向きは多くの場合，構想から具体へ，全体から詳細へ，背景から展開へという流れになっています．構成を考える手がかりにしてください．

## 出力

`awami_skeleton.json` という名前の，ダウンロードできる JSON ファイルとして出力してください．
ファイルの中身は次の形の JSON オブジェクト一つだけにします．

```json
{
  "format": "awami-skeleton",
  "version": 1,
  "canvas_id": 1,
  "title": "文書の標題",
  "subtitle": "副題（任意）",
  "lead": "冒頭の導入文（Markdown，任意）",
  "sections": [
    {
      "heading": "節の見出し",
      "text": "節の導入文（Markdown，任意）",
      "nodes": [
        {"id": 63, "label": "FUJINプロジェクト", "depth": 0},
        {"id": 64, "label": "FUJIN-P によるDXの考え方", "depth": 1, "rel": "具体化",
         "comment": "この文書を置く理由や読みどころ（Markdown，任意）"}
      ],
      "sections": [
        {"heading": "下位の節", "text": "…", "nodes": [], "sections": []}
      ]
    }
  ],
  "closing": "結び（Markdown，任意）"
}
```

各節は，見出し，導入文，ノードの並び，下位の節の順に展開されます．

## 規則

canvas_id には，ダンプの metadata.canvas_id を写してください．
nodes[] の id にはダンプの nodes[].id を使い，label にはそのノードの label をそのまま写してください（照合に使います）．
ダンプに無いノードや URL を作り出さないでください．
文書内での見出しをノードのラベルと変えたいときだけ，"title" を加えてください．
depth は節の中での字下げの深さ（0 から）です．結合子でつながった親子を depth で表すと読みやすくなります．
rel には，そのノードを直前の親ノードと結ぶ結合子の名前を書きます（任意）．
同じノードは原則として 1 回だけ置いてください．2 回目以降は本文を繰り返さず「文書 k と同じ」と表示されます．
節は 3 階層までにしてください．
lead・text・comment・closing は短い Markdown にとどめます．本文はノードの文書から流し込まれるので，ここでは文書と文書をつなぐ説明に徹してください．
作りたい文書の趣旨に合わないノードは入れなくて構いません．
文体は依頼者の指定に従い，指定がなければ「である」調とし，句読点は「．」「，」を使ってください．

## ファイルの外で報告すること

スケルトンのファイルとは別に，チャットの返答で次の二つを短く報告してください．
採用しなかったノードとその理由．
構成上の判断で依頼者に確かめたい点（あれば）．
