# テーコンに同梱する対応式の見本

ここに置いてあるのは，対応式（絵エクセルとふつうのSQLテーブル群との対応）の書き方の見本である。
テーコンの「新しい対応式」の画面に貼り込めば，そのまま使える。

## spec_gyomu_jisseki.json — 年度業務実績報告書 ④小項目別評価

節（大項目×中項目）の帯が繰り返し，その下に中期計画がぶら下がる様式。
中期計画には，小見出しが番号と同じ行に来る形・小見出しだけが一行を占める形・小見出しの無い形の
三通りがあり，`when` でどの形だったかを `form` 列に残している。

実物の一枚（436行・結合セル446個）で確かめた結果は次のとおり。

- 行の署名は 16 種類しかなかった
- 帯に合ったのが 366 行，残余に落ちたのが 70 行
- 枠は 909 のうち 825（90.8%）が対応式で説明された
- 絵 → 表 → 絵 の往復で **差分ゼロ**（xlsx ファイルに書き出して読み直しても同じ）

残余に落ちた 70 行は，第９〜第14（予算・短期借入金・不要財産・重要財産・剰余金・その他）の
二列表・三列表である。この対応式はそこを説明していないが，残余として控えられるので
往復では元どおりに戻る。必要になったらその形の帯を足せばよい。
**説明できていないところが数で見える**のが，この分解のよいところである。

## spec_jikanwari.json — 時間割表（下書き）

一つのセルに何件も詰まっている様式の見本。曜日は様式の側の軸なので枠の位置で表し，
セルの中身は `list` で子の表（一コマ一件の授業）へほぐす。

実物のエクセルをまだ預かっていないので，列番号と帯の高さは仮である。
標本を預けて「行の署名」を見てから合わせること。

## 対応式を新しくこしらえるとき

1. テーコンに絵エクセルを預ける
2. 「生成AIへの依頼文」を写して生成AIに渡す（文法の説明と，そのシートの署名・素描が入っている）
3. 返ってきた JSON を「新しい対応式」に貼る
4. 「試す」で分解してみる。SQL には何も書かれない
5. 往復の差分がゼロになり，残余が納得のいく大きさになるまで直す
6. テーブルを作り，版（データセット）を決めて分解を通す
