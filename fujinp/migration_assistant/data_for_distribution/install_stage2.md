## 第2段階 — 一般のアプリを取り込む

第1段階で立ち上がったサイトに，一般のアプリを全部載せます．
使うのは，第1段階と同じ全アプリパッケージ（`fujinp_apps_overview_<日時>.json`）です．
カーネル・admin・アプシャは第1段階で書き出した日の版になっているので，そろえ直す作業はありません．

作業はすべてアプシャの画面から行います．コンソールは，ライブラリを足すときだけ使います．
立ち上げたサイトに admin でログインし，管理者ダッシュボードのアプシャのカードからアプシャを開いてください．
取り込みは admin だけが行えます．

## 1. 全アプリパッケージを選ぶ

アプシャの「🛠 管理」タブを開き，「📥 全アプリパッケージからの取り込み」で全アプリパッケージを選びます．
大きいファイルなので，一覧が出るまでしばらくかかります．
ここではまだ何も書き込まれていません．

一覧の一番上にはカーネルの行があり，パッケージの版とこのサイトの版が並びます．
第1段階を済ませたばかりなら，両方が同じ版になっています．
その下に，admin とアプシャ，一般のアプリが，こちらのサイトとの新旧（新規・更新あり・同じ・こちらが新しい）つきで並びます．
立ち上げたばかりのサイトなら，一般のアプリは全部「新規」になっているはずです．

## 2. まとめて取り込む

新規と更新ありのアプリには最初からチェックが入っています（「全選択」「全解除」「新規・更新のみ」で切り替えられます）．
admin とアプシャは第1段階で入っているので，チェックは要りません．
「テーブルの宣言・改訂を適用する（足すだけ）」に印が付いていることを確かめて，「📥 選択したアプリを取り込む」を押します．

チェックしたアプリが1本ずつ順に処理され，1本ごとに，退避 → 配置 → 正本 → 文書 → 台帳 → テーブル → 不具合 → 発行の順で入ります．
アプシャ自身を選んだときは，最後に取り込まれます．
結果の欄に「⚠ 不足テーブル」が出たアプリは，その行の「個別に検証」で取り込み画面に送り，テーブルの宣言を確かめてから適用し直します．

## 3. ライブラリを入れて Reload する

アプリによっては，`requirements.txt` に無いライブラリを使います．
いまの FUJIN-P のアプリが使う pip のライブラリは次のとおりです．

```text
pip3.13 install --user pytz pandas numpy openpyxl pypdf beautifulsoup4 requests slack_sdk
```

PythonAnywhere には最初から入っているものが多いので，入っていれば何も起きません．
数字は Web タブの Python の版に合わせます．
アプリごとの一覧は，アプシャの管理画面でアプリを開いた「ライブラリ」タブにも出ています．

入れ終わったら，取り込みの結果の欄の「Reload」か，Web タブで Reload します．

## 4. 定数を確かめる

元のサイトの `config.py` を置いたときは，アプリが使う定数（Slack のトークン，Google Drive の認証情報など）もすでに入っています．
雛形から書いたときは，アプシャの管理画面でアプリを開き，「定数」タブに出ている必須のものを `config.py` に足し，Reload します．

## 5. 仕上がりを確かめる

管理者ダッシュボードに，元のサイトと同じカードが並んでいることを確かめます．
アプシャのダッシュボードで，各アプリのカードの版が元のサイトと同じであることを確かめます．

この時点では，テーブルの中身は空です．
データは別の手順で戻します．
データを戻すとアプシャの台帳も保全した時点のものに入れ替わるので，戻したあとにもう一度「📢 発行」と Reload を行います．

## うまくいかないときの確認順

取り込んだのにダッシュボードにカードが出ないときは，アプシャの管理画面でそのアプリを開き，「ランチャ」タブを見てください．
カードの使用区分と表示先のダッシュボードが，今のログイン相手と合っているかを確かめます．
合っていれば，「📢 発行」と Reload をもう一度行います．

カードはあるが押すとエラーになるときは，Blueprint が登録されていません．
Web タブのエラーログを見て，`ModuleNotFoundError` なら 3 のライブラリを入れて Reload します．

画面は出るがデータで落ちるときは，テーブルが足りていない可能性があります．
管理画面の「テーブル」タブで，台帳にある表が実際に作られているかを比べられます．
差があれば，その画面から作れます．

`config.py` に関するエラーが出るときは，4 に戻って定数を足します．

アプシャやカーネルを差し替えたあとにアプシャが開けなくなったときは，Bash コンソールで次を実行して Reload します．
カーネル・admin・アプシャのファイルが全アプリパッケージの版に戻ります．テーブルとデータには触りません．

```text
cd ~
python3 fujinp_bootstrap.py fujinp_apps_overview_<日時>.json --files --force
```

## あとでカーネル・admin・アプシャを更新するとき

カーネルは，アプシャの「🧩 カーネル取り込み」で，カーネルの JSON か全アプリパッケージを選んで取り込みます．
admin とアプシャは，一般のアプリと同じく，カードの「📥 取り込み」か，この画面の全アプリパッケージからの取り込みで差し替えます．
どれも取り込みのあとに Reload します．

## 元に戻したいとき

アプリを外すには，アプシャの管理画面でそのアプリを削除します．
正本・文書・テーブル台帳・不具合の記録が消え，ダッシュボードからカードが消えます．
ファイルとテーブルの実体は残ります．消すかどうかは，中のデータを見てから決めてください．
kernel・admin・アプシャの3行は削除できません．
