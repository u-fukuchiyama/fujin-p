## 第2段階 — 版をそろえ，全アプリを取り込む

第1段階で立ち上がった種を，元のサイトと同じ版にそろえ，そのうえで全アプリを載せます．
使うのは，全体マニュアルの「用意するもの」にある次の4つのファイルです．

カーネルの JSON（`fujinp_kernel_<日時>.json`）
アプシャのパッケージ（`app_package_app_share_<日時>.json`）
admin のパッケージ（`app_package_admin_<日時>.json`）
全アプリパッケージ（`fujinp_apps_overview_<日時>.json`）

作業はすべてアプシャの画面から行います．
立ち上げたサイトに admin でログインし，管理者ダッシュボードのアプシャのカードからアプシャを開いてください．
取り込みは admin だけが行えます．

順は，アプシャ → カーネル → admin → 全アプリ，です．
アプシャを最初にするのは，カーネルの取り込みの画面が新しいアプシャにしか無いためです．

## 1. アプシャをそろえる

アプシャのダッシュボードで，アプシャ（app_share）のカードの「📥 取り込み」を押します．
「1. パッケージ JSON を選ぶ」でアプシャのパッケージを選ぶと，検証の結果が出ます．
ここではまだ何も書き込まれていません．
「既存アプリの差し替え」と出ていることを確かめます．

「テーブルの宣言・改訂を適用する（足すだけ）」に印が付いていることを確かめて，「⚙ 適用」を押します．
種のアプシャの表に足りない列と表（区画の色，背景の表など）が，ここで足されます．
適用前のファイルは `fujinp/app_share/import_backups/` に退避されます．

適用が済んだら，PythonAnywhere の Web タブで Reload します．
画面に「Reload が必要」と出ていれば，そこの「🔄 Reload」でも構いません．

Reload のあとアプシャを開き直し，アプシャのカードの版が，取り込んだパッケージの版（`version_id`）になっていることを確かめます．

## 2. カーネルをそろえる

アプシャのダッシュボードで kernel（_platform）のカードの「🛠 管理」を押し，「版」のタブを開いて「📥 カーネル取り込み」を押します．
カーネルの JSON を選ぶと，ファイルごとに新規・変更・同じが並び，パッケージの版と手元の版が出ます．
ここではまだ何も書き込まれていません．

「取り込み後に Reload する」の印を外してから，「⚙ 取り込む」を押します．
カーネルの新しいコードと古い admin の組み合わせで Reload すると，起動に失敗するおそれがあるためです．
Reload は，次の admin を取り込んでからまとめて行います．

カーネルの取り込みは，`config.py` と `fujinp/app_registry.json` を書きません．
書き込む前のファイルは `~/kernel_backups/<日時>/` に写され，`restore.py` が置かれます．
画面に出る元に戻すためのコマンドを控えておいてください．

## 3. admin をそろえる

アプシャのダッシュボードに戻り，admin のカードの「📥 取り込み」で admin のパッケージを選びます．
「既存アプリの差し替え」と出ていることを確かめて，「⚙ 適用」を押します．

適用が済んだら，Web タブで Reload します．
Reload のあと，アプシャの「📢 発行」を押します．

ここで，サイトが開き，admin でログインでき，管理者ダッシュボードにアプシャのカードがあることを確かめます．
アプシャを開き，kernel・admin・アプシャの3枚のカードの版が，それぞれ保全したファイルの版と一致していることを確かめます．
サイトが開かないときは，末尾の「うまくいかないときの確認順」を見てください．

## 4. 全アプリを取り込む

アプシャの「🛠 管理」タブで「📥 全アプリパッケージからの取り込み」を開き，全アプリパッケージを選びます．
含まれるアプリの一覧が，こちらのサイトとの新旧（新規・更新・同じ・古い）つきで出ます．
立ち上げたばかりのサイトなら，全部が「新規」になっているはずです．
ここではまだ何も書き込まれていません．

新規のアプリには最初からチェックが入っています（「全選択」「全解除」「新規・更新のみ」で切り替えられます）．
「テーブルの宣言・改訂を適用する（足すだけ）」に印が付いていることを確かめて，「📥 選択したアプリを取り込む」を押します．
チェックしたアプリが1本ずつ順に処理され，1本ごとに，退避 → 配置 → 正本 → 文書 → 台帳 → テーブル → 不具合 → 発行の順で入ります．
結果の欄に「⚠ 不足テーブル」が出たアプリは，その行の「個別に検証」で取り込み画面に送り，テーブルの宣言を確かめてから適用し直します．

全アプリパッケージは大きいので，選んでから一覧が出るまでしばらくかかります．
「検証失敗」と出て一覧が出ないときは，Web タブのエラーログを見て原因を確かめてください．

## 5. ライブラリを入れて Reload する

アプリによっては，種に入っていないライブラリを使います．
アプシャの管理画面でアプリを開き，「ライブラリ」タブに出ている pip のライブラリを入れます．

```text
pip3.13 install --user <名前>
```

数字は Web タブの Python の版に合わせます．
入れ終わったら Web タブで Reload します．

## 6. 定数を確かめる

元のサイトの `config.py` を置いたときは，アプリが使う定数（Slack のトークン，Google Drive の認証情報など）もすでに入っています．
雛形から書いたときは，アプシャの管理画面でアプリを開き，「定数」タブに出ている必須のものを `config.py` に足し，Reload します．

## 7. 仕上がりを確かめる

管理者ダッシュボードに，元のサイトと同じカードが並んでいることを確かめます．
アプシャのダッシュボードで，各アプリのカードの版が元のサイトと同じであることを確かめます．

この時点では，テーブルの中身は空です．
データは別の手順で戻します．
データを戻すとアプシャの台帳も保全した時点のものに入れ替わるので，戻したあとにもう一度「📢 発行」と Reload を行います．

## うまくいかないときの確認順

1 のあとにアプシャが開かなくなったときは，Web タブのエラーログを見ます．
`fujinp/app_share/import_backups/app_share_<日時>/` に適用前のファイルが残っているので，Bash コンソールでそれを `fujinp/app_share/` に戻して Reload すると，種のアプシャに戻ります．

3 のあとにサイトが開かなくなったときは，まず Web タブのエラーログを見ます．
カーネルが原因なら，2 の画面で控えたコマンド（`python3 ~/kernel_backups/<日時>/restore.py`）で，カーネルを取り込む前の状態に戻ります．
admin が原因なら，`fujinp/app_share/import_backups/admin_<日時>/` のファイルを `fujinp/admin/` に戻して Reload します．

取り込んだのにダッシュボードにカードが出ないときは，アプシャの管理画面でそのアプリを開き，「ランチャ」タブを見てください．
カードの使用区分と表示先のダッシュボードが，今のログイン相手と合っているかを確かめます．
合っていれば，「📢 発行」と Reload をもう一度行います．

カードはあるが押すとエラーになるときは，Blueprint が登録されていません．
Web タブのエラーログを見て，`ModuleNotFoundError` なら 5 のライブラリを入れて Reload します．

画面は出るがデータで落ちるときは，テーブルが足りていない可能性があります．
管理画面の「テーブル」タブで，台帳にある表が実際に作られているかを比べられます．
差があれば，その画面から作れます．

`config.py` に関するエラーが出るときは，6 に戻って定数を足します．

## 元に戻したいとき

アプリを外すには，アプシャの管理画面でそのアプリを削除します．
正本・文書・テーブル台帳・不具合の記録が消え，ダッシュボードからカードが消えます．
ファイルとテーブルの実体は残ります．消すかどうかは，中のデータを見てから決めてください．
kernel・admin・アプシャの3行は削除できません．
