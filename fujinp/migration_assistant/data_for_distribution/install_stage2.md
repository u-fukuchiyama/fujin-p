## 第2段階 — アプシャでアプリを取り込む

第1段階で立ち上がった種に，アプリを1本ずつ載せていきます．アプリ1本は，ファイル・正本（起動情報とランチャ）・テーブル・文書・既知の不具合をひとまとめにした JSON ファイル1本で運びます．これをアプリパッケージと呼びます．

取り込みはアプシャの画面から行います．コンソールもファイル操作も要りません．

## 1. 配布元でパッケージを作る

配布元のサイト（アプリが動いているサイト）に admin でログインし，アプシャを開きます．

取り込みたいアプリのカードにある 📦 エクスポートを押します．文書の点検を訊かれたら，そのまま出すなら「今は更新不要」を選びます．JSON ファイルが1本ダウンロードされます．

複数のアプリをまとめて出すこともできます．アプシャの右上にある ⬇ 全アプリパッケージのエクスポートから，1本ずつ点検したうえで全アプリ分の JSON を1本にして書き出します．取り込む側では，その中から必要なアプリだけを選べます．

アプシャ自身とカーネルは，一括の書き出しには入りません．種に既に入っているので，取り込む必要もありません．

## 2. 取り込む側で検証する

立ち上げたサイトに admin でログインし，アプシャを開きます．

カードの 📥 取り込み（または管理タブの新規取り込み）を押し，1 で受け取った JSON を選びます．

まず検証が走ります．画面に出るのは，新規か更新か，入るファイルの数，増えるテーブル，必要な定数，既存のテーブルとの差です．ここではまだ何も書き込まれていません．

赤い表示が出たら，適用せずに内容を読んでください．よくあるのは，必要な定数が `config.py` に無い，という指摘です．

## 3. 適用する

内容を確かめたら適用します．次の4つがまとめて行われます．

アプリのファイルが `fujinp/<アプリ名>/` に置かれます．既にある場合は，適用前のディレクトリが `import_backups/` に退避されます．

正本にアプリの行が登録され，起動情報（Blueprint）とランチャ（ダッシュボードのカード）が入ります．

テーブルが作られます．同じ名前のテーブルが既にある場合は，列の追加と索引の追加だけが自動で行われ，型の変更や削除は表示だけして手を触れません．

マニュアルと技術仕様書が登録され，既知の不具合も引き継がれます．

最後に正本が発行され，`fujinp/app_registry.json` が書き直されます．

## 4. 定数を足す

そのアプリが必要とする設定（Slack のトークン，Google Drive の認証情報など）があれば，`config.py` に足します．

何が要るかは，アプシャの管理画面でそのアプリを開き，「定数」タブを見ると分かります．必須のものと任意のものが分かれて並んでいます．

Files 画面で `config.py` を開いて `Config` クラスに行を足し，保存します．

## 5. Reload する

Web タブの緑の Reload ボタンを押します．新しく登録された Blueprint は，ここで初めて有効になります．

ダッシュボードに戻ると，そのアプリのカードが出ています．出ない場合は 6 を見てください．

## 取り込む順

先に入れておくと後が楽なものがあります．

まいぐる（`user_groups`）は，グループによる表示の出し分けを他のアプリが使います．早めに入れてください．

ゆーまい（`user_migration`）は，配布元のユーザを移すためのアプリです．利用者を移す予定があるなら，アプリより先に入れます．

マイノート（`my_md_notes`）は，アプシャの文書編集画面の画像アップロードが依存しています．入れると，その機能が動くようになります．

残りは，使いたいものから順で構いません．

## うまくいかないときの確認順

取り込んだのにダッシュボードにカードが出ないときは，アプシャの管理画面でそのアプリを開き，「ランチャ」タブを見てください．カードの使用区分（公開・機関内・グループ・管理者のみ）が，今のログイン相手と合っているかを確かめます．合っていれば，発行と Reload をもう一度行います．

カードはあるが押すとエラーになるときは，Blueprint が登録されていません．Web タブのエラーログを見ます．`ModuleNotFoundError` なら，そのアプリが使うライブラリが入っていません．アプシャの管理画面の「ライブラリ」タブに一覧があるので，`pip3 install --user <名前>` で入れて Reload します．

画面は出るがデータで落ちるときは，テーブルが足りていない可能性があります．管理画面の「テーブル」タブで，台帳にある表が実際に作られているかを比べられます．差があれば，その画面から作れます．

`config.py` に関するエラーが出るときは，4 に戻って定数を足します．

取り込み自体が失敗したときは，`fujinp/<アプリ名>/import_backups/` に適用前のファイルが残っています．

## 元に戻したいとき

アプリを外すには，アプシャの管理画面でそのアプリを削除します．正本・文書・テーブル台帳・不具合の記録が消え，ダッシュボードからカードが消えます．

ファイルとテーブルの実体は残ります．消すかどうかは，中のデータを見てから決めてください．
