## 第2段階 — アプシャでアプリを取り込む

第1段階で立ち上がった種に，アプリを載せていきます．全アプリをまとめて載せることも，1本ずつ載せることもできます．アプリ1本は，ファイル・正本（起動情報とランチャ）・テーブル・文書・既知の不具合をひとまとめにした JSON ファイル1本で運びます．これをアプリパッケージと呼びます．

取り込みはアプシャの画面から行います．コンソールもファイル操作も要りません．

## 1. 配布元からパッケージを持ち帰る

配布元のサイト（アプリが動いている FUJIN-P サイト）にログインし，アプシャを開きます．admin である必要はありません．構成員でもゲストでも，ログインできればパッケージを持ち帰れます．FUJIN-P はオープンソース（AGPL v3）なので，配布元のアプリは誰でも自分のサイトに組み込めます．

全部まとめて持ち帰るときは，「⬇ 全アプリパッケージ」を押します．全アプリ分をまとめた JSON が1本ダウンロードされます．取り込む側では，その中から必要なアプリだけを選べます．

1本だけ持ち帰るときは，アプリ一覧でそのアプリの「📦 パッケージ」を押します．そのアプリの JSON が1本ダウンロードされます．

アプシャ自身とカーネルは，全アプリパッケージには入りません．種に入っているので，取り込む必要はありません．アプシャを配布元と同じ新しさにしたいときは，アプシャのカードの「📦 パッケージ」で持ち帰り，こちらのアプシャのカードの 📥 取り込みで入れます．「⚙ カーネル」で出る JSON は，いま動いているカーネルと見比べるための参照用です．新しいサイトの立ち上げには，第1段階の導入スクリプトを使います．

配布元が開発中で非公開にしているアプリは，配布元の admin 以外には出てきません．

配布元の admin が自分で書き出すときは，アプシャの管理画面の「📦 エクスポート」「⬇ 全アプリパッケージエクスポート」を使います．こちらはマニュアルと仕様書の点検を1本ずつ済ませてから書き出す手順になります．

## 2. 取り込む側で検証する

立ち上げたサイトに admin でログインし，アプシャを開きます．取り込みは admin だけが行えます．

全アプリパッケージを取り込むときは，「🛠 管理」タブの「📥 全アプリパッケージからの取り込み」で，1 で持ち帰った JSON を選びます．含まれるアプリの一覧が，こちらのサイトとの新旧（新規・更新・同じ・古い）つきで出ます．ここではまだ何も書き込まれていません．取り込むアプリにチェックを入れて進めると，チェックしたアプリが順に 3 の手順で適用されます．初めてのサイトなら，全部が「新規」になっているはずです．

1本ずつ取り込むときは，新しいアプリなら「📦 新規アプリ取り込み」，すでにあるアプリならそのカードの 📥 取り込みを押し，1 で持ち帰った JSON を選びます．まず検証が走ります．画面に出るのは，新規か更新か，入るファイルの数，増えるテーブル，必要な定数，既存のテーブルとの差です．ここではまだ何も書き込まれていません．

赤い表示が出たら，適用せずに内容を読んでください．よくあるのは，必要な定数が `config.py` に無い，という指摘です．

## 3. 適用する

内容を確かめたら適用します．次の4つがまとめて行われます．

アプリのファイルが `fujinp/<アプリ名>/` に置かれます．既にある場合は，適用前のディレクトリが `fujinp/app_share/import_backups/` に退避されます．

正本にアプリの行が登録され，起動情報（Blueprint）とランチャ（ダッシュボードのカード）が入ります．

テーブルが作られます．同じ名前のテーブルが既にある場合は，列の追加と索引の追加だけが自動で行われ，型の変更や削除は表示だけして手を触れません．

マニュアルと技術仕様書が登録され，既知の不具合も引き継がれます．

最後に正本が発行され，`fujinp/app_registry.json` が書き直されます．

## 4. 定数を足す

そのアプリが必要とする設定（Slack のトークン，Google Drive の認証情報など）があれば，`config.py` に足します．

何が要るかは，アプシャの管理画面でそのアプリを開き，「定数」タブを見ると分かります．必須のものと任意のものが分かれて並んでいます．

Files 画面で `config.py` を開いて `Config` クラスに行を足し，保存します．

## 5. Reload する

Web タブの緑の Reload ボタンを押します．新しく登録された Blueprint は，ここで初めて有効になります．

ダッシュボードに戻ると，そのアプリのカードが出ています．出ない場合は 6 を見てください．

## 取り込む順

先に入れておくと後が楽なものがあります．

まいぐる（`user_groups`）は，グループによる表示の出し分けを他のアプリが使います．早めに入れてください．

ゆーまい（`user_migration`）は，サイト間でユーザを移すためのアプリです．利用者を移す予定があるなら，アプリより先に入れます．

マイノート（`my_md_notes`）は，アプシャの文書編集画面の画像アップロードが依存しています．入れると，その機能が動くようになります．

残りは，使いたいものから順で構いません．

## うまくいかないときの確認順

取り込んだのにダッシュボードにカードが出ないときは，アプシャの管理画面でそのアプリを開き，「ランチャ」タブを見てください．カードの使用区分（非公開・ゲストにも・構成員だけ・グループ・構成員＋グループ・公開）と表示先のダッシュボードが，今のログイン相手と合っているかを確かめます．取り込んだカードの使用区分は配布元での設定のままなので，こちらのサイトの運用に合わせて変えてください．合っていれば，発行と Reload をもう一度行います．

カードはあるが押すとエラーになるときは，Blueprint が登録されていません．Web タブのエラーログを見ます．`ModuleNotFoundError` なら，そのアプリが使うライブラリが入っていません．アプシャの管理画面の「ライブラリ」タブに一覧があるので，`pip3.13 install --user <名前>`（数字は Web タブの Python の版）で入れて Reload します．

画面は出るがデータで落ちるときは，テーブルが足りていない可能性があります．管理画面の「テーブル」タブで，台帳にある表が実際に作られているかを比べられます．差があれば，その画面から作れます．

`config.py` に関するエラーが出るときは，4 に戻って定数を足します．

取り込み自体が失敗したときは，`fujinp/app_share/import_backups/<アプリ名>_<日時>/` に適用前のファイルが残っています．

## 元に戻したいとき

アプリを外すには，アプシャの管理画面でそのアプリを削除します．正本・文書・テーブル台帳・不具合の記録が消え，ダッシュボードからカードが消えます．

ファイルとテーブルの実体は残ります．消すかどうかは，中のデータを見てから決めてください．
