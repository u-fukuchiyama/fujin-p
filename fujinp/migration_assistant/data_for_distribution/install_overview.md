## 別サイトへのインストール — 全体マニュアル

新品の PythonAnywhere に FUJIN-P を立ち上げ，元のサイトと同じ版のカーネルとアプリを載せるまでの道筋です．
稼働中のサイトを保全したファイルから作り直すときにも，ほかのサイトから FUJIN-P を持ち込むときにも，同じ手順で進めます．
作業は2つの段階に分かれます．

第1段階で，カーネルとアプシャだけの「種」を立ち上げます．
終わると，admin でログインして管理者ダッシュボードが出て，そこにアプシャのカードがある状態になります．
アプリはまだ1本も入っていません．

第2段階で，種をアプシャ・カーネル・admin の順に元のサイトと同じ版にそろえ，そのあと全アプリを取り込みます．

段階の間に，人が手で行う設定がいくつか挟まります．
データベースの作成，`config.py` の用意，WSGI の設定，最初の admin の登録の4つです．
テーブルの中身（データ）は，この手順では戻しません．別の手順で戻します．

## 用意するもの

元のサイトのアプシャで書き出した次の4つのファイルを使います．

| ファイル | 中身 | 元のサイトでの書き出し方 |
|---|---|---|
| `fujinp_kernel_<日時>.json` | カーネル（ホーム直下のコード，`templates/`，`fujinp/registry.py`）．導入スクリプト `fujinp_kernel_install.py` も中に入っている | kernel（_platform）の管理画面の「版」の「📦 カーネルエクスポート」（カードの「📦 エクスポート」でも同じ） |
| `app_package_app_share_<日時>.json` | アプシャ | アプシャのカードの「📦 エクスポート」 |
| `app_package_admin_<日時>.json` | アカウント管理と，管理者・ゲストのダッシュボード | admin のカードの「📦 エクスポート」 |
| `fujinp_apps_overview_<日時>.json` | アプシャ・カーネル・admin を除く全アプリ | アプシャの「⬇ 全アプリパッケージエクスポート」 |

4つは同じ日に続けて書き出し，そろいで保管します．
カーネルと admin とアプシャは全アプリパッケージに入らないので，3つとも別に書き出す必要があります．
元のサイトで admin として書き出してください．admin 以外で書き出したカーネルは，公開用に絞り込んだ版になります．

もう1つ，`config.py` が要ります．
`config.py` はどのファイルにも入っていません．
保全では元のサイトの `config.py` を別に控えておき，それを使います．
新しく作るときは，カーネルに入っている `config_template.py` から書きます．

PythonAnywhere の有料アカウント（Developer プラン以上）も要ります．
FUJIN-P はデータベース（MySQL）を全面的に使うので，無料プランでは動きません．
Web タブで Flask の Web アプリを1つ作っておきます．Python の版は元のサイトに合わせます（いまの FUJIN-P は 3.13 で動いています）．

## 全体の流れ

```text
  ┌─ 第1段階 ─────────────────────────────┐
  │  カーネルの JSON から導入スクリプトを取り出す
  │  fujinp_kernel_install.py --files      ← ファイル展開（自動）
  │  α  データベースを作る                   ← 手動
  │  α  config.py を置く                    ← 手動
  │  fujinp_kernel_install.py --schema     ← テーブル作成・正本の発行（自動）
  │  α  WSGI を設定して Reload              ← 手動
  │  α  最初の admin を登録                 ← 手動（make_admin.py が文を作る）
  └────────────────────────────────────────┘
            ↓  admin でログインできる／アプシャが動く
  ┌─ 第2段階 ─────────────────────────────┐
  │  アプシャを取り込む → Reload
  │  カーネルを取り込む → Reload
  │  admin を取り込む → Reload
  │  全アプリパッケージから取り込む → ライブラリを入れる → Reload
  └────────────────────────────────────────┘
```

## 所要時間の目安

第1段階が30分ほど，第2段階が30分ほどです．
つまずきやすいのは，第1段階の `config.py` と WSGI の設定，第2段階のライブラリの導入です．

## 段の順にこだわる理由

導入スクリプトに入っている種は，スクリプトを作った日のカーネルとアプシャです．
元のサイトのカーネルやアプシャがそれより新しければ，種のままでは版がずれます．
第2段階の最初に，アプシャ・カーネル・admin を保全した版で上書きし，元のサイトとそろえます．

アプシャを最初に上書きするのは，カーネルの取り込みがアプシャの新しい版の機能だからです．
古い種のアプシャにはカーネルの取り込みの画面がありません．

## 配布ファイル

導入スクリプト [fujinp_kernel_install.py](/migration_assistant/dist/fujinp_kernel_install.py) は，新しいサイトのホーム直下（`/home/<アカウント名>/`）に置いて使います．
ふつうはカーネルの JSON から取り出すので，ダウンロードが要るのはカーネルの JSON が手元に無いときです．
組み立て道具 [build_installer.py](/migration_assistant/dist/build_installer.py) は，配布元のサイトで導入スクリプトを作り直すときに使います．
配布元のサイトでは `~/fujinp/migration_assistant/` に入っているので，`python3 ~/fujinp/migration_assistant/build_installer.py` で実行します．
どちらのダウンロードにも，配布元の FUJIN-P サイトへのログインが要ります．

## 段階ごとの手引き

第1段階の手順は「第1段階マニュアル」に，第2段階の手順は「第2段階マニュアル」に，それぞれ順を追って書いてあります．
うまくいかないときは，まずその段階のマニュアルの末尾にある確認順を見てください．

## この手順で戻らないもの

テーブルの中身（利用者，各アプリのデータ）は戻りません．別の手順で戻します．
アプリの配下に置かれた投稿ファイル（キターレオンライン審議や研究倫理審査の提出書類など）と `static/` も戻りません．ファイルとして別に移します．
Scheduled Task（日次の点検など）と GitHub の関所は，PythonAnywhere の画面とコンソールで作り直します．
