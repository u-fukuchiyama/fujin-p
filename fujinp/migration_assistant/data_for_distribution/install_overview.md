## 別サイトへのインストール — 全体マニュアル

新品の PythonAnywhere に FUJIN-P を立ち上げ，元のサイトと同じ版のカーネルとアプリを載せるまでの道筋です．
稼働中のサイトを保全したファイルから作り直すときにも，ほかのサイトから FUJIN-P を持ち込むときにも，同じ手順で進めます．
作業は2つの段階に分かれます．

第1段階で，カーネルとアプシャまでを立ち上げます．
使うのは立ち上げスクリプト `fujinp_bootstrap.py` で，Bash コンソールから実行します．
終わると，admin でログインして管理者ダッシュボードが出て，そこにアプシャのカードがある状態になります．
一般のアプリはまだ1本も入っていません．

第2段階で，立ち上がったサイトのアプシャの画面から，一般のアプリをまとめて取り込みます．
コンソールは使いません．

テーブルの中身（データ）は，この手順では戻しません．別の手順で戻します．

## 用意するもの

元のサイトのアプシャで書き出した全アプリパッケージ（`fujinp_apps_overview_<日時>.json`）を1つ使います．
書き出し方は，元のサイトのアプシャのダッシュボードの「⬇ 全アプリパッケージエクスポート」です．
元のサイトで admin として書き出してください．admin 以外で書き出したものは，カーネルが公開用に絞り込んだ版になります．

全アプリパッケージには，サイト1つ分のプログラムが全部入っています．

| 入っているもの | 中身 |
|---|---|
| `bootstrap.kernel` | カーネル（ホーム直下のコード，`templates/`，配布用静的ファイル `static_for_distribution/`，`fujinp/registry.py`）．立ち上げスクリプト `fujinp_bootstrap.py` もここに入っている |
| `bootstrap.platform` | 共通テーブル（`users` など）の定義 |
| `bootstrap.admin` | アカウント管理と，管理者・ゲストのダッシュボード |
| `bootstrap.app_share` | アプシャ |
| `apps` | 一般のアプリ全部 |

入っていないのは `config.py` だけです．
保全では元のサイトの `config.py` を別に控えておき，それを使います．
新しく作るときは，カーネルに入っている `config_template.py` から書きます．
Google 認証と Slack は FUJIN-P の外のサービスなので，`config.py` に元のサイトと同じ値を写すだけでは動きません．
その設定は手引き「[外部サービス設定（Google認証・Slack）](/migration_assistant/guide/external)」にまとめてあります．

PythonAnywhere の有料アカウント（Developer プラン以上）も要ります．
FUJIN-P はデータベース（MySQL）を全面的に使うので，無料プランでは動きません．
Web タブで Flask の Web アプリを1つ作っておきます．Python の版は元のサイトに合わせます（いまの FUJIN-P は 3.13 で動いています）．

## 全体の流れ

```text
  ┌─ 第1段階（Bash コンソール） ─────────────────┐
  │  α  データベースを作る                     ← 手動（Databases タブ）
  │  α  全アプリパッケージをアップロード          ← 手動（Files 画面）
  │  JSON から fujinp_bootstrap.py を取り出す     ← コマンド1行
  │  fujinp_bootstrap.py <JSON> --files         ← ファイル書き出し（自動）
  │  pip でライブラリを入れる                    ← コマンド
  │  α  config.py を書く                        ← 手動
  │  fujinp_bootstrap.py <JSON> --schema        ← テーブル作成・正本の登録と発行（自動）
  │  α  WSGI を設定して Reload                  ← 手動（Web タブ）
  │  fujinp_bootstrap.py <JSON> --admin         ← 最初の admin を登録
  └──────────────────────────────────────────┘
            ↓  admin でログインできる／アプシャが動く
  ┌─ 第2段階（アプシャの画面） ─────────────────┐
  │  同じ JSON を「全アプリパッケージからの取り込み」で選ぶ
  │  選んだアプリをまとめて取り込む → Reload
  └──────────────────────────────────────────┘
```

## 所要時間の目安

第1段階が30分ほど，第2段階が15分ほどです．
つまずきやすいのは，第1段階の `config.py` と WSGI の設定，第2段階のライブラリの導入です．

## 2つの段階に分ける理由

一般のアプリを取り込むのはアプシャの仕事で，アプシャはサイトが立ち上がってからでないと動きません．
そこで，アプシャが動くところまでをスクリプトで立ち上げ，そこから先をアプシャに任せます．
第1段階で入るカーネル・admin・アプシャは，全アプリパッケージを書き出した日の版そのものです．
立ち上げたあとに版をそろえ直す作業はありません．

## アプシャが開けなくなったとき

アプシャやカーネルを差し替えたあとにサイトやアプシャが開けなくなったら，全アプリパッケージと立ち上げスクリプトで立て直せます．
Bash コンソールで次を実行し，Web タブで Reload します．

```text
cd ~
python3 fujinp_bootstrap.py fujinp_apps_overview_<日時>.json --files --force
```

カーネル・admin・アプシャのファイルが，その JSON の版に戻ります．
書き換える前のファイルは `fujinp_bootstrap_backup_<日時>/` に退避されます．
テーブルとデータには触りません．

## 配布ファイル

立ち上げスクリプト [fujinp_bootstrap.py](/migration_assistant/dist/fujinp_bootstrap.py) は，全アプリパッケージの中に入っているので，ふつうはダウンロードは要りません．
JSON から取り出す方法は，第1段階マニュアルの手順2にあります．
JSON の中から取り出せないときだけ，このリンクから受け取ります．受け取るには，配布元の FUJIN-P サイトへのログインが要ります．

## 段階ごとの手引き

第1段階の手順は「第1段階マニュアル」に，第2段階の手順は「第2段階マニュアル」に，それぞれ順を追って書いてあります．
うまくいかないときは，まずその段階のマニュアルの末尾にある確認順を見てください．

## この手順で戻らないもの

テーブルの中身（利用者，各アプリのデータ）は戻りません．別の手順で戻します．
アプリの配下に置かれた投稿ファイル（キターレオンライン審議や研究倫理審査の提出書類など）は戻りません．ファイルとして別に移します．
`static/` は，配布用静的ファイル（規約類・アイコンなど）だけが入ります．それ以外のものは別に移します．
Scheduled Task（日次の点検など）と GitHub の関所は，PythonAnywhere の画面とコンソールで作り直します．
